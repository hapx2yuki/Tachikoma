# P15 電源・動作シミュレータ

## 位置付け

`tools/power-system-simulator/`には、旧P14接続案を前提に作られたP15数値シミュレータを、任意のソフトウェア確認用ツールとして同梱しています。P36/P37の実配線、基板・BOMの採用状態、実機ファーム、サーボの実応答を実装したものではありません。電源を操作したり、実機へ指令したりする機能はありません。

これは既存P15の移植であり、実機停止・電池監視仕様の追加ではありません。P15内のモデル機能を製品仕様・実機停止要求・電池監視要求へ昇格させません。電池監視と停止時扱いは未決定のままです。

## 現行配線との対応

| 項目 | P36 S1 / P37 の現行基準 | P15が表す範囲 |
|---|---|---|
| 脚サーボ | LiPo 2S → XT60 → 既存主ヒューズ → P36 F1 → 脚12軸。PCA9685のV+は使わない | 12軸の計算モデルと、PCAから独立したサーボ電源枝はある。電池・共通線・脚線の電圧降下を仮定値で計算するが、P36配線形状は表さない |
| F1 / 主ヒューズ | P36 F1は交換候補15A。定格・保護協調・実負荷適合は未確定 | P15は`fuseEnabled=false`が初期値で、任意の仮想I²t遮断を1つ持つ。実時間電流特性ではなく、既存主ヒューズとP36 F1を別々に表さない |
| 腕 | UBECからMG90S×4 | 腕4軸とUBEC相当の変換枝を持つ。既定部品はHENGE 8A参照モデル。現物UBECの版・設定との一致は未確認 |
| 制御 | ESP32はMINI560から5V、PCA9685×2 | MINI560は既定で5V/3A/効率90%/差電圧2Vというモデル仮定。PCA9685のPWM量子化を一部計算するが、CPU・完全なI²C・全レジスターは実行しない |
| バッテリー | LiPo 2S、XT60。実機の内部抵抗・電圧曲線は未測定 | 既定のZeee 2S 2200mAh参照、XT60そのものは電気モデル外。SOC-OCVと0.06Ωの内部抵抗は仮定 |

**P15はP36/P37全体へパラメータ変更だけでは追随できません。** 12脚+4腕、2S電池、腕のUBEC、5Vロジックなど一部の枠は対応します。一方、独立した既存主ヒューズと脚分配基板上のF1を直列・別位置として持つ経路はなく、1つの仮想保護要素とグローバルな主電源状態しかありません。回路トポロジーの追加が必要になるため、今回は変更せずP15をlegacy modelとして明示します。

特に、P15のLD-220MG 3Aストール電流、MG90S 0.85A、バッテリー抵抗・SOC曲線、変換器の制限動作はモデル値または仮定です。P36の15A候補を実負荷に適合する定格とみなしたり、12台の最大・拘束電流が確定したとみなしたりしません。P36電流評価の試験候補条件と、P15の計算出力は別の証拠です。

画面の角度・電流・電圧・SOCは数値モデルの計算値です。波形は実測ではなく、モデルの実機妥当性、基板電流容量、保護協調、熱、歩行成立性を証明しません。P15の低電圧停止もソフトウェア内の任意モデル動作で、現物に停止経路があることを意味しません。

## 起動と検証

リポジトリのルートから次でAPIモニターを起動します。`/`は`monitor.html`を返します。`index.html`のブラウザ内操作画面はツールREADMEのPython静的サーバー手順で開きます。

```sh
node tools/power-system-simulator/server.cjs
```

Node.js 18以降が必要です。追加パッケージは不要です。API・制御例は[ツールのREADME](../../tools/power-system-simulator/README.md)と[インターフェース仕様](../../tools/power-system-simulator/INTERFACE.md)を参照してください。

2026-11-08のパッケージ確認はNode.js v25.3.0で数値テスト12/12 PASS、APIテスト17/17 PASSでした。Nodeサーバーから`/`と`/index.html`および必要なJS/CSS/HTML資産をHTTP 200で取得し、`/api/state`、`/api/command`、`/api/step`もHTTP 200でした。16軸の計算状態が返り、応答の`physicalValidation`は`NOT_RUN`です。サーバープロセスは確認後停止しました。ブラウザ描画・波形の視覚確認と実機検証は行っていません。
