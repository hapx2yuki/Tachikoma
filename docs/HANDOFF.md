## §4 設計の鉄則 (背景と実例)

1. **見える形状は元キット準拠**: 独自造形の目・腕は 2 度ユーザーに棄却された (付録 #27/#29)。
   準拠の型は (a) そのまま印刷 (b) 中抜き/内部加工して被せ (c) 正規化して機構に取込، の 3 つ。
   誤って「未使用」と断定して元形状を削るのは鉄則違反 (#49 で実際に発生し復元)
2. **0.1mm 精度・実メッシュ検証**: 手計算・目視は端点しか見ず中間で外す (#10)。
   ブーリアン/レイキャスト/signed_distance で数値化する
3. **config.py 一元化**: firmware・チェッカー・docs へ複製された定数は必ず drift した
   (ARM_REACH_MM #31、HIP_DROP 5 ファイル散在 #40、literal 12 が 8 ファイル散在)。
   消費側は config.py 参照 or config.h regex 実読
4. **UNVERIFIED 規律**: 価格・寸法・物性など未確認値は「UNVERIFIED + 相場/文献値 + 確認日」で
   記録。「確認済み」と書いてよいのは実出力・実測・実ページ取得の証拠があるときだけ
5. **ガードは 2 段 (target + cur_)**: スルーレートで軸ごとに到達時刻が違うため、
   目標側だけのクランプは遷移中に必ず破れる (#16 — 数値再現済み)。重畳 (wave 等) →
   クランプ → スルーレートの順序も固定
6. **到達可能集合基準**: gait.h のワークスペース射影 (D_KNEE_MIN/MAX) が出力できない姿勢は
   実機で発生しない — その姿勢だけで起きる干渉は「実害なし」と分類してよい
   (`pk_reachable()` が厳密判定)。ただし (a) firmware に歩容非経由の関節指令経路を
   追加したらこの前提は崩れる、(b) URDF を直接駆動するシミュレータでは適用外
7. **レンダ証拠は新規プロセス + mtime 確認**: `_MESH_CACHE` の stale 画像で
   「修正確認済み」と誤報した実害あり (before/after が同一 MD5 だった)

## 付録 A: 設計の落とし穴集 (54 項目)

再発しやすい失敗と回避策。元は前任エージェントのメモリにあったものを全量移植した。
(#番号は発見順。関連チェッカーに恒久化済みのものも多いが、**新規設計時に同じ推論ミスを
繰り返さない**ためのカタログとして残す)

1. **スプロール立位では股ピッチが大きく負になるのが正常** (体高115で約-21°、掃引全域で-45°まで)。リミットを「見た目の常識」で-20°に絞ると歩容IKが全滅する。
2. **膝サーボ角の規約が2通り混在しやすい**: firmware は femur 相対角。干渉チェッカーを絶対角で書くと過酷すぎる姿勢を検査してしまう (check_leg_assembly は firmware 規約に統一済み)。
3. **遊脚時に膝が最も折れる**: 接地時でなく足上げ (STEP_H) 時に膝リミットへ達する。体高最小値はここで決まる。
4. **併進+旋回の同時指令で合成歩幅が上限超過**: 歩幅ベクトルのノルムクランプが必須 (gait.h 実装済み)。
5. **tibia 上部構造は膝±45°回転で femur 側に刺さる**: 旧解は左右対称の 45°ウェッジ面取りだったが、femur は膝軸の股側 (-X) にしか無く、+X 側まで削った結果ネックが 11mm² (SF 0.1) に痩せていた (2026-09-04 M-01)。現在は femur 側障害物 (箱枠+ウェブ) の ±47° 回転掃引領域を数値的に減算し、外側 3mm 増厚 (make_leg.py `_femur_knee_sweep`)。**幾何だけでなく断面応力も見る** (`check_leg_link_strength.py`)。
6. 元モデルの小パーツはブーリアン加工に耐えない (φ18穴で崩壊)。装飾は接着対応にする。
7. **干渉チェックにサーボ実体を忘れるとケース貫通を全部見落とす**: STD サーボはタブ下 28.2mm が反対側へ突き出る。チェッカーはサーボダミー (実寸) を合体させて検査する。
8. **ブーリアンの順序バグ 2 種**: (a) ポケット減算後に正形状を足すとポケットが埋まる → 正形状を全合成してから負形状を最後にまとめて引く。(b) 面取り後にビームを足すと掃引域に角が残る。
9. **薄板へのサーボポケット素通し**: タブビスの肉がゼロになる。台座ボスを盛ってから引く (check_screw_bosses が実測)。
10. 手計算の干渉判定は端点だけ見て中間点を見落とす。必ず数値ブーリアンで裏取り。
11. フィラメント見積りは「体積×充填率」だと大型ソリッドで過大評価。表面積×壁厚+インフィルの物理モデルを使う (tools/filament_calc.py)。
12. **マウント穴は「ポケット開口と重ならないか」まで見る**: 回転配置の開口は角が回る。穴位置は回転後矩形の4隅で照合し、最後は実メッシュ contains で裏取り。
13. **ミラー対称ペイロード (両腕) は互いに衝突する**: 単体安全でもミラーモードで両手が中心線へ同時に寄る。重畳→クランプ→スルーレートの順を固定。
14. 粗い作業域近似 (円柱コリドー) は保守的すぎて成立解を潰すことがある。粗近似のままなら docs にその旨明記。
15. **回転駆動の軸方向は「何の座標を変えたいか」から逆算して検証**: 回転では回転軸方向の座標は変わらない (グリッパ駆動不能バグの根本原因)。
16. **ソフトリミットを目標角だけで評価しない**: スルーレート追従中は先着軸が「まだ来ていない姿勢」を根拠に過大角を許される。target と cur_ の両方で評価。
17. **実物のリファレンスを最初に確認する**: キャラクターものは機能設計の前にシルエット決定要素 (付け根位置・プロポーション) を実物/設定画で固定する (腕マウント全面再設計の教訓)。
18. 無限円柱で脚をモデル化すると過保守。高さ帯別 (コクサ/大腿/脛/足元) にモデル化する。
19. **lib ヘルパーを「材の向きが逆」の部品で再実装すると符号ミスが混入**: 負形状の z 範囲を 1 個ずつ書き出して材側にあるか確認。チェッカーのプローブ点は代表 1 点にしない。
20. **幾何が正しくても「組立順」が物理的に実行可能かを別途検証**: ドライバーの進入経路まで含めて手順を追う (密閉ポッドの中心ビスは物理的に締められなかった)。
21. **ファーム内の同名変数は「意味」で照合**: vx/vy の取り違え (このプロジェクトは +Y が前)。速度系引数は意味名 (vfwd 等) にする。
22. **「顔」パーツは造形の意味論まで実物に合わせる**: 機構が同じでも見た目の解釈を誤ると別物になる。
23. **matplotlib 3D はコレクション単位の平均深度で前後合成**: 近接メッシュは 1 つの Poly3DCollection に結合して面単位 zsort。
24. **[要実測] タグの値を設計前提にする前に、手元にモデルがあるなら先に測る**: 仮定値ベースのチェックは形状と無関係に OK を返し続ける。
25. **性能主張の式は「実際に動く点」の半径で立てる**: 一度は独立した数値シミュレーションで裏取り。
26. **放射状マウントの「尻尾」は中心で収束する**: 開口側だけのチェックは盲点。裏側の尾部間距離も実測。
27. **「顔」パーツは独自造形せず元キット形状を機構側へ取り込む**: 2 回の独自造形が 2 回棄却された。元メッシュの正規化流用をまず検討。
28. **輸入メッシュとのブーリアンは STL 往復で非 watertight になりやすい**: Manifold.simplify(0.01) で解決。trimesh の process 自体が壊すこともある (raw 再構築フォールバック)。
29. **「元パーツベース」は方針として最初に確定させる**: 全パーツを実測してから設計する。キットの左右非対称のような発見がある。
30. **可動化した元パーツ被せには関節の逃がしセクタが必ず要る**: 実リンクメッシュの回転ブーリアン (複数角度) で干渉 0 を検証。
31. **firmware へ複写した幾何定数は必ず drift する**: 検証スクリプトは config.h を実ファイル regex 読取で取得し実寸と突合。「firmware 挙動の再現」(複製定数) と「物理量の評価」(実寸) は別変数で持つ — 同一変数だと恒等式になり検査にならない。
32. **輸入メッシュ×箱ブーリアンは殻を非連結化する** (watertight でも別ボディに割れる): 負形状は必要範囲に限定 + 生成側 decompose() で最大連結成分のみ + 検証側で split()==1 を恒久チェック。
33. **完成図を見ずに部品名から解剖を推測しない**: Cabin は背中のポッド、前面の球体が頭 (2 段階のユーザー指摘で発覚)。スケールは全パーツ一律 ×1.5 のみ (部分リサイズ禁止)。
34. **統合基板はキットのハブ部品寸法に合わせて最初から設計**: 足先位置は STANCE_R で維持できる。移設系は隣接サブシステムへの副作用検査までがセット。
35. **trimesh の鏡映 (負行列) を boolean に入れると偽陰性/NaN**: ミラー形状は manifold3d の .mirror() で STL 出力するか座標符号反転で直接生成。trimesh 側の鏡映は描画専用。
36. **回転対称の同一脚 4 本は取付間隔 ≥90° 専用**: 45° ペア配置では対角脚をミラー版 (_m) にして張り出しを逃がす + 2 段ヨークランプ。
37. **干渉検査は「サーボ空間全域」と「IK 到達域」を区別**: IK が原理的に出力しない姿勢は運用で起きない。手ポーズ/校正時の注意は docs に明記して線引き。
38. **公式フィギュアの下面が配置の正**: フリクションクランプ関節に固定角は存在しない。真値は完成写真の実測から。シェル配置は意匠特徴の実測方位で必ず照合。
39. **非対称放射配置の歩容は (スタンス角, SWAY, LEAD) の連成調整**: パラメータスキャンで解く。副作用 (リーチ超過・内側ヨー増) の常時突合を sim に組み込む。
40. **「残す肉厚」は切削式から導出して書く**: 内腔寸法は `H - wall - flange` のような残厚導出式で。取付ボルト座面はレイキャストで実測プローブ。
41. **円筒インサートの薄肉と回転位置**: スロット切削後の残リブ厚を数値検証。円形ポケット部品にはキー突起で誤挿入を物理的に防ぐ。貫通穴の縁のレイキャスト肉厚 0 は測定アーチファクト (開口境界を除外)。
42. **音声ストリーミングの双方向流量は両端で契約**: 送信側に実時間ペーシング、終端シグナルは try/finally で保証、再接続時は状態再送。AsyncTCP はコア分離。
43. **iPhone テザリングは既定 5GHz (iPhone 12+)**: ESP32-WROOM は 2.4GHz 専用で無言で失敗。「互換性を最大にする」ON を手順の最初に。
44. **3MF の Metadata/model_settings.config に元アセンブリ座標が残っている**: source_offset の単純加算で相対配置が復元できる — 組立フォレンジクスの正攻法。ただし同一 source_object_id クラスタ内のみ有効。
45. **±40° 移設後の腕相互クランプはデッドコード化に注意**: マウント方位 > リミットだと横変位クランプが常時フロア。移設系タスクは「空いた/塞がった場所」の再検査までがセット。
46. **フォレンジクス finding も敵対検証してから設計へ反映**: 「touch すべきペアで gap 0」がメソッド妥当性の裏付けであり、非接触ペアの値は独立検算必須 (誤値の実例あり)。
47. **「見える/使える」系の検証は必ず全アセンブリを対象に**: 部分メッシュ検証は自己遮蔽しか見えない。カメラ FOV 80% 遮蔽の見落としが実例 (現在は 8 姿勢全アセンブリ掃引を恒久化)。
48. **ミラー脚に載る装飾はフィット行列もミラーする**: diag(1,-1,1,1)+invert() の後適用で厳密同値。「_m 版には _m 用の装飾配置」をチェックリスト化。
49. **等分仮定や「らしい」配置で妥協する前に取付フィーチャーを個別実測**: トゥのスタブは非等間隔だった。装飾の一部を「未使用」と誤断定して元形状を削るのは鉄則違反。
50. **接地校正は SWAY 込みの実歩容ロジックで二分探索**: IK 用実効長 (TIBIA_LEN_GAIT=153.6) と物理長 (135) は別定数で持つ。
51. **ゴースト変換の「法線の回し忘れ」はバグクラス**: 方向ベクトルも位置と同じ変換連鎖を通す。パーツのローカル軸は Z とは限らない。回転対称部品のロールは写真照合で確定。
52. **写真照合は「特徴の同定」から間違える**: まず「そのピクセルはどのパーツか」を周辺特徴で同定。物理チェーンの露出量は調整パラメータではなく嵌合実寸の従属量。
53. **準対称形状の 180° 反転は適合指標に映らない (flip-blindness)**: シーム/リング一致で向きを確定しない。非対称フィーチャーの分布と写真で判定。反転仮説テストを監査の標準項目に。
54. **カンチレバー梁の強度は「断面係数最小の一点」では代表できない**: σ(y)=M(y)/Z(y) を全区間スキャンして最大値を取る (check_pod_neck_strength.py に恒久化)。真の最弱点はレバーアーム支配で基部側にあった。

55. **PyBullet は本機 (macOS SDK 26) でビルド不能** (同梱 zlib の K&R 記法非互換、wheel も無し)。物理シムは MuJoCo (`.venv` 導入済み) を使う。
56. **MuJoCo の安定化**: 陽解法 Euler + damping 0 は立位だけで発振転倒する。implicitfast 積分 + 全関節 armature 0.001 / damping 0.02 で解決 (tools/sim_physics.py 参照)。
57. **STL 往復は頂点順序非決定**: メッシュ同一性の比較は頂点インデックスやソート比較ではなく三角形コーナー点群の KDTree 最近傍で行う。
