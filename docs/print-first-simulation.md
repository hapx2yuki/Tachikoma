# 追加購入を避ける歩容・重量配置の旧候補比較

2026-09-05。**これは旧脚形状を使った候補選別の履歴であり、LD-220MG 対応の新しい機構が歩けるという最終判定ではない。** 通常構成の STL、URDF、firmware はこの比較では変更していない。print-first用の追加ヘッダーは通常モードから分離した試験入力であり、改修機構の確定後に同じ条件を新しい質量・接触・取付形状で実行する。

省部品の低負荷profileは電装のビルド構成だけを変え、**幾何・歩容・サーボ定数は共通・未変更**です。この文書の予備シムは旧靴・旧機構を入力にしているため、低負荷profileが新しい靴やLD-220MGの歩行を証明するものではありません。最終機構のシムでは、採用STL・質量・接触材料を一度だけ反映し、最大鉛直接触力と水平接触力を別々に保存します。

最終統合ケースの `model` には、各脚のφ10プラグ根元を次の形で渡します。`leg_foot_bored` の足フレーム原点 `(0, 0, 0)` を、物理形状の `C.TIBIA_LEN=135.0 mm` だけ `-Z` へ移した脛リンク局所座標です。足フレーム→脛フレームの移動をシム側で再度足しません。`axis_local` は脛の `+Z` 軸で、接触点ごとの `Σ(r×F+τ)` を曲げ/ねじりへ分解するために使います。

```json
{
 "model": {
  "pla_phi10_plug_roots": {
   "FR": {"frame": "tibia", "xyz_mm": [0, 0, -135.0], "link": "leg_fr_tibia", "axis_local": [0, 0, 1]},
   "FL": {"frame": "tibia", "xyz_mm": [0, 0, -135.0], "link": "leg_fl_tibia", "axis_local": [0, 0, 1]},
   "RL": {"frame": "tibia", "xyz_mm": [0, 0, -135.0], "link": "leg_rl_tibia", "axis_local": [0, 0, 1]},
   "RR": {"frame": "tibia", "xyz_mm": [0, 0, -135.0], "link": "leg_rr_tibia", "axis_local": [0, 0, 1]}
  }
 }
}
```

この座標が無い旧ケースでは、接触荷重の記録は残してもφ10根元の強度値を合格判定へ使いません。`model_kind` が `final_integrated` 系のケースには実行器が同じ座標を補いますが、最終STL・脛リンク・足候補が凍結した後に入力台帳と一緒に再確認します。

`model_kind` が `final_integrated`、`print_first_final`、`frozen_integrated` のケースは実行前ゲートを通す。`assembly_context=true`、旧URDFではない存在する最終URDF、`contact_model=vhacd` 等の材料別凸分解、`self_collision=true`、`include_servo_collision=true`（`include_servos`）、`include_parent_collision=true`、4脚の根元座標、凍結時刻と凍結ハッシュがそろわなければ `UNVERIFIED` として拒否する。固定5組のプロキシ例外は台帳へ明示し、指定した有限native traceの全姿勢を実メッシュ自己衝突検査へ束縛する。未完の監査は有限検査の合格へ昇格せず、凍結済みの幾何・質量・入力があればオフライン物理計算の個別結果だけを保存する。通常の旧感度ケースへこの既定値は波及しない。

`include_parent_collision=true` でMuJoCoの親子link衝突を有効にし、固定5組だけをレビュー済みの例外として扱う。`tools/sim_self_collision.py` などで指定した有限native traceの全姿勢を実メッシュのBoolean交差として別途検査する。有限個のC++姿勢・軌道を確認した結果と、連続した到達集合を証明した結果は分けて記録し、連続集合の証明が無い場合は `continuous_reachable_set_proven=false` を情報上の限界として残す。凸包接触、足底接触、床接触だけの結果は最終全機のPASSに昇格しない。物理条件のFAIL/FALL/数値失敗はそのまま保持する。

最終統合の物理計算が内部条件を満たしても、`sim_print_first.py` の結果は `PENDING_EXTERNAL_PROXY_PROOF` として保存する。固定5組を含む全リンクの実STL証明、密掃引、今回サンプリングしたqposの監査を `check_print_first_proxy_exclusions.py` が完了して初めて、統合結果を有限検査の合格へ結合する。

最終ケースの `freeze_manifest` は、凍結時点の台帳ファイル自身のSHA-256と時刻に加え、最終URDF、そのURDFが参照する全STL、組立台帳が参照するSTL、`hardware/src/config.py`、PlatformIO設定、firmwareの全ヘッダー/`main.cpp` の行別SHAを記録する。実行前に現在のファイルを再計算して台帳と突合し、1つでも欠損・改変・旧URDFとの混在があれば `UNVERIFIED` として入口で拒否する。凍結時刻とハッシュ文字列だけを記載したケースは、実形状の凍結を証明しない。

最終ケースの `group_voltage_V` は `leg`、`arm`、`eye` の3群を必ず明示する。実行器は凍結した元URDFを変更せず、ケース別の `*-voltage-limited.urdf` を作り、関節の `effort` と `velocity` だけを旧メーカー端点からの参照内挿値へ差し替える。質量・慣性・原点・メッシュは複製前後で保持し、`model_manifest.voltage_limits` と結果の `voltage_limit_report` で全20関節のMuJoCo上限と要求値を突合する。LD-220MGの6 Vトルク、速度、連続保持能力を測定した結果ではないため、これがPASSでも実機定格の合格とは解釈しない。

現段階では、股ヨー軸半径 85 mm、足先相対半径 105 mm、体高 115 mm、歩幅 18 mm、揚程 8 mm、周期 2.4 秒、支持率 0.90、腕振り 0 度が再試験候補である。負荷を下げる効果はあるが、直進指令で向きがずれるため、現物用の採用値はまだ確定しない。新しいサーボや電源の購入は前提にしていない。

## 現物と参照計算値

対象品のうち、現物報告 [#99](https://github.com/hapx2yuki/Tachikoma/issues/99) の対象個体は LD-220MG と記録されている。**記録上の候補14個すべての同型・外形寸法は未照合**で、14個全数をLD-220MGとしてこのシムへ反映していない。メーカーは 20 kg·cm と 0.16 秒/60度を **7.4 V** で記載し、動作電圧を 6～8.4 V、重量を 66 g としている。**6 V でのトルク・速度・連続保持能力は公表値から確定できない。** 6 V へ給電する方針と、7.4 V の能力を得られることは別である。記録上の候補に関する公式仕様（2026-09-05 確認）

今回の初期比較は、既存 URDF の DS3218 由来の参照上限 1.9559 N·m、無負荷速度 7.0334 rad/s を起点にしている。LD-220MG の 6 V を再現した数値ではない。トルク上限 50%＝0.97794 N·m、70%＝1.36912 N·m、速度上限 70%＝4.92339 rad/s も比較する。減率は脚だけでなく全サーボへ同時適用する感度条件である。脚 6 V、腕 5 V、目 5 V の設定名も、旧メーカー値から作った参照内挿値であり、各購入品の適合確認ではない。

電装構成は [省部品構成の配線と確認](print-first-electrical.md) に記載する。機械仕事率が小さくても、静止保持電流、始動電流、配線の電圧降下、HENGE の連続能力、発熱は証明できない。本比較から「HENGE で電流が足りる」とは結論していない。

## 比較範囲と再現方法

[実行器](../tools/sim_print_first.py) は、実際の `Gait`、`LegOutput`、`Arms`、`Servos` を出力ディレクトリへ複製し、指定した定数だけを変えて C++ でコンパイルする。PCA9685 の 50 Hz の量子化後の 20 軸出力を MuJoCo へ渡す。通常 firmware の既定値は変更せず、print-first用の追加ヘッダーと複製側の定数を試験時だけ使う。腕振りを 0 度にしても、脚と腕の干渉ガードによる退避動作は残る。

- 予備選別: 体高 115～155 mm、足半径 85～129 mm、前後オフセット -30～-10 mm、重心移動量 3 段階の 225 条件と基準 1 条件。さらに股軸半径 75/80/85 mm の 27 条件、半径・前後位置・重心移動の組合せ 36 条件を比較した。
- 各静的条件: 前後・左右・左右旋回の 6 指令、64 位相。実際のヨー制限後の順運動学を使う。ただし足を等価接地点に置き換え、鉛直荷重の釣合いだけを解く。脚自身の質量モーメント、接地形状、樹脂強度、動的効果はこの段階では含まない。
- 動的条件: 2 ms 刻み、接地摩擦 0.60 と 0.35、硬い足部 0.30、線形トルク・速度包絡、既存の分割凸包接触モデル。旧監査の TPU 靴候補を使う。新規の `feet/assembly.json` による足とは別の形状である。
- 積分直後の全 500 Hz 標本から各脚軸の平均、95/99 パーセンタイル、最大トルクを集計する。従来の 10 Hz 記録だけから最大負荷を評価しない。実接触点と重心投影の支持余裕は 100 Hz で記録する。
- 初期状態は保持角へ整列した状態で、足が床に接するように配置する。起動時の脱力、20 軸の順次通電、0 度から立ち上がる遷移の証明には使わない。自己衝突もこの予備比較では無効であり、新しいケースや取付部の干渉を見逃してよいという意味ではない。

幅を変える比較では、ヨー関節の XY 位置を移し、旧モデルのヨーサーボ質量だけを移動して慣性を再計算する。新しいシャーシの形状はまだ入れていない。総質量 2.91779 kg の条件は、旧モデル＋旧靴に仮の構造 100 g とサーボ差分を想定した 72 g を**ベースへまとめて加えた感度条件**である。66 g の LD-220MG を 12 個、正しい位置へ配置したモデルではない。重心移動条件もベース質量全体の平行移動で、棚や電池の実際の移設を再現していない。

## 比較から分かった制約

足半径 85 mm の静的候補では、等価点支持の最大モーメントを基準の約 1.61 から 1.04 N·m へ減らせる。しかし多数の姿勢でヨー制限に当たり、動的な支持余裕の下位値も悪化した。静的なトルク値だけを根拠に、この半径を採用しない。

股軸を 75→85 mm へ広げると、同じ足半径・姿勢で点支持余裕は増える一方、脚モーメントはわずかに増える。幅広シャーシによって低い頭位置を残せるかは、収納・強度側の成立条件と合わせて判断する。脚リンク長を変える案や、新しいサーボ購入による解決は、この探索では前提にしない。

支持率を 0.82→0.90 に延ばす方が、揚程を 8→12 mm に増やしたり、腕を振ったりするより負荷低下に有効だった。滑らかな遊脚曲線も比較したが、選定姿勢の負荷改善は小さいため、現段階では正規の曲線を保つ候補を優先する。C++ 複製内の変更箇所と各実行の定数は `firmware/*/build.json` と `cases/*.json` に残る。

ベース重心を高くする感度条件は、旧支持率 0.82 で支持余裕の下位値を悪化させた。重心を前へ動かせば必ず良くなるわけでもなく、前方 30 mm の移動では向きのずれが増えた。後方 20 mm は進路を改善したが、脚トルクも少し増えた。棚の位置はこの傾向だけで固定せず、最終配置の総重心で再評価する。

## 検証器側の修正

候補周期 3.2 秒で C++ と Python の停止位相が分かれた。原因は、正規 C++ の `float` と比較側 Python の倍精度による四分の一周期境界の丸め差だった。今回の実行器内の位相更新を C++ と同じ単精度演算に合わせた。1280 フレーム比較で最大角差 0.0000307 度、位相差 0.00000000005 以下、代替 IK なしを確認した。正規 firmware の停止処理は変えていない。

同じ設定名を続けて再実行した際、出力した実行ファイル `compare` が C++ 標準ヘッダー `<compare>` と衝突した。実行ファイルを `bin/` へ分離し、同一設定での繰り返しコンパイルが通るようにした。修正前の中断ログ・結果は `history/` と `selected-before-compile-path-fix.log` に保持している。この中断を物理的な転倒と数えない。

## 再実行と次の統合

```sh
.venv/bin/python tools/sim_print_first.py scan --out outputs/print-first-recheck
.venv/bin/python tools/sim_print_first.py run \
 --out outputs/print-first-recheck \
 --cases outputs/print-first-20260905/simulation/selected-cases.json
.venv/bin/python tools/sim_print_first.py run \
 --out outputs/print-first-recheck \
 --cases outputs/print-first-20260905/simulation/combined-cases.json
```

既存の証拠を上書きしないため、再実行先を別ディレクトリにする。`models/*.urdf` はその実行時の元メッシュ絶対パスを含むので、別環境ではケースから再生成する。保存すべき根拠は、条件 JSON、入力 SHA-256、C++ 複製ソースと変更点、結果 JSON、支持時系列、集計図である。`firmware/*/bin/` の実行ファイルと `collision-cache/*.npz` はローカルの再生成可能物であり、配布には不要。

次の統合では、LD-220MG の保持・ホーン変換部、新しいシャーシ・棚・頭受け・固定爪・足靴の全質量を一度だけ反映し、旧部品が自動追加されていないことを確認する。そのモデルで今回の候補、弱いトルクと速度の組合せ、低摩擦、停止・逆旋回、長時間前進、実際の起動、自己衝突を再実行する。最終モデルの成立と、6 V での実測支持・温度・電源降下がそろうまでは、実機製作完了・歩行実証済みとは扱わない。
