**LED・microSD・追加の停止回路を買わず、既存候補と開放式の印刷棚で先へ進む構成です。** 脚、腕、左右の目、I2S音声、独立カメラの機能を残します。初期段階で保留するのは、WS2812の発光とDFPlayerのSD効果音です。通常版の機能は削除せず、別のビルド構成として追加しました。

### 脚サーボの型番確定と残る条件

現物報告の対象個体ではLD-220MG、取付耳なし、旧coxaへ入らないこと、ケーブル出口の違い、金属円盤ホーンの付属を確認しています（[現物課題 #99](https://github.com/hapx2yuki/Tachikoma/issues/99)、関連 #100〜#103）。この報告を14個全数の型番・寸法確認とは扱いません。旧DS3218のケース・ホーン・20 kg·cm@6 Vを流用して適合済みとはしません。

LD-220MGの公式仕様は6〜8.4 V、20 kg·cm@7.4 V、66 g、500〜2500 µsで180°、周期20 msです。したがってHENGEの6 V案は許容電圧内ですが、**6 Vのトルク・連続保持・電流は未確認**です。公式仕様画像の拘束電流2.4〜3 Aも印加電圧が書かれておらず、連続運転許容や6 Vでの値には置き換えません。

本体は既に`US_MIN=500`/`US_MAX=2500`/`DEG_RANGE=180`、`1500 + deg × 2000 / 180`で出力するため、名目のPWM範囲は一致します。1000〜2000 µsへ狭める変更はしていません。実中立、発振器補正、可動端と荷重側の角度対応は単体校正を残します。取付は付属円盤ホーンと印刷保持部で再設計し、旧ケースへの押込みや取付耳の流用を前提にしません。

## 電源は3系統へ分ける

```text
2S LiPo +
 └─既存ヒューズ─既存の手動スイッチ─┬─HENGE入力 → 6 V 脚バス → 記録上の候補×12
                   ├─mini560 #1 → 5 V ロジック → ESP32 / MAX98357A / XIAO
                   └─mini560 #2 → 5 V 腕・目バス → MG90S×6 / ES9251II×2
2S LiPo − ──────────────── 共通GND（各変換器・基板・サーボへ）
ESP32 3.3 V ───────────── PCA×2のVCC / INMP441 VDD
```

- **各変換器の正出力同士をつながない。** 5 V同士でも並列化せず、#1と#2は別負荷へ分配します。GNDだけを共通にします。
- 電池・HENGE幹線は既存候補AWG16、各分岐は負荷と長さを確認したAWG20を使います。サーボ電源はPCAのV+端子・基板パターンへ集中させず、外部配線から分配します。
- SPL82を使う場合、まず無通電で**内部の導通グループ・許容線径・DC定格**を実物で確認します。全差込口が同じ電位と思い込まないでください。端子の定格が未確認なら、大電流を通して合格した扱いにはせず、既存太線の接続方法を含めEL-01で確定します。
- 電解1000 µF/16 Vを脚6 Vバスに1個、腕・目5 Vバスに1個、470 µF/10 Vをロジック5 V側に1個、極性を合わせて置きます。既存600個セットの実値・耐圧を先に確認します。これは配置案であり、過渡電流の測定を済ませた値ではありません。
- ESP32の5 V/VINへはmini560 #1だけを接続します。PCA VCCは3.3 V、サーボV+とは別です。PCAのSDA/SCLの待機電位も約3.3 Vであることを確認します。[PCA端子の一次資料](https://learn.adafruit.com/16-channel-pwm-servo-driver/pinouts)
- HENGEの購入名は5/6 V・瞬間12 Aです。連続8 A、入力下限7 Vという旧メモを現物定格の代わりにしません。mini560も購入名の5 Aを、熱条件を問わない連続出力保証にはしません。
- 6 V脚/5 V腕目の定格と保持力を実物で確認します。許容電圧が一致しない場合はまず手持ち予備と設計を照合し、定格不明品へ試しに高電圧を掛ける手順にはしません。5 Vの腕・目が必要荷重を保持できるかは未試験です。

USBで本体を扱う際は**mini560 #1→ESP32 5 V線を外してからUSBを挿す**。通常運転ではUSBを抜いて5 V線を戻します。XIAOにもUSBと外部給電を重ねない配線にします。USBが残ると主スイッチOFFでも一部ロジックが生きるため、手動全電源停止の確認ではUSB等の外部電源をすべて外します。[Espressifの給電条件](https://documentation.espressif.com/esp-dev-kits/en/latest/esp32/esp32-devkitc/user_guide.html)

### 電池監視は省かない

```text
電池+（主スイッチ後） ─100 kΩ─●─33 kΩ─GND
                 └─ GPIO34
```

抵抗を単独で測って100 kΩと33 kΩを選び、接続後はGPIO34側と電池側の電圧を確認します。8.4 Vに対する分圧の計算値は約2.08 Vです。配線確認に使う計算例であり、実測値ではありません。

現行ソフトの警告6.8 V、6.4 V未満の継続で停止する値は変更していません。**この値はHENGEが6 Vを維持できる下限の保証ではありません。** 初期試験は測定済みの電池電圧範囲内で短く行い、HENGE出力低下・再起動・異常な発熱/動作があれば手動停止します。起動時に分圧線が未実装・断線・範囲外なら`UNVERIFIED`として通常のstand/ready/PWMを禁止します。校正版でも、明示した`/cal?ch=<使用中ch>&us=<軸別保護範囲内>`の1軸診断だけがこのゲートを迂回し、全軸同時出力や電気的端点は許可しません。立たせる前にWebのVBATとDT830Bを毎回照合します。

Web telemetry の`vbat_verified`/`vbat_state`はGPIO34の電池分圧線だけを確認します。PCA9685のサーボV+レールを読むセンサはこの手持ち構成にないため、`servo_rail_verified=false`、`servo_rail_state=UNVERIFIED_NO_SENSOR`を実機確認まで維持します。VBATが正常でもV+の未接続・断線はソフトだけでは分かりません。量産・全軸通電の前には、既存主電源スイッチをOFF、USBを抜き、支持台上でPCAのOE端子が使える場合はOE=HIGH（出力禁止）にしてからV+を接続し、V+電圧をテスターで確認します。OEを出力許可へ戻した後、Web UIの「立つ」を一度押して再アームします。VBATゲートを失った後はfirmwareがfull-offとWS所有権を解除するため、V+の後接続だけで以前のstandが復活することはありません。OEを操作できない基板では、手元の既存主電源スイッチによる停止を実機ゲートにします。

状態変更のHTTP操作(`/arm`、`/eye`、`/trim`、`/wifi`、`/play`、校正版`/cal`)は、操作WebSocketが有効な間は同じ画面が受け取った一時`session`値を付けた要求だけが通ります。別タブ・別端末は409で拒否され、所有者不在時は`confirm=1`の明示操作だけが通ります。`/play`の200は1〜9999の整数を再生キューへ積んだ結果で、DFPlayerのSDファイル存在までは確認しません。

## I2S音声は手持ち線で短く組む

ESP32近くの開放式印刷棚にはMAX98357Aアンプを置き、`tools/print_first_assembly.py` が保持する `mic_cannon` と `speaker_cannon` は既存の砲身位置に残します。マイク/スピーカーを棚へ移したとは扱わず、棚から既存位置までの配線を外観変更を許した配線溝・タイラップ受けで保持します。狭い既存の首穴を通すことは条件にしません。既存候補AWG26は手持ちPAW-32で処理できるので、AWG30専用工具と6ピンコネクタは初期に買いません。AWG30を使うのは、その被覆を損ねず処理できる手段がある場合だけです。

| 接続元 | 接続先 | 配線 |
|---|---|---|
| ESP32 GPIO26 | INMP441 SCK、MAX98357A BCLK | 近くで2分岐。AWG26の短い信号線 |
| ESP32 GPIO25 | INMP441 WS、MAX98357A LRC | 近くで2分岐 |
| ESP32 GPIO33 | INMP441 SD | 録音データ。アンプのSD端子とは別 |
| ESP32 GPIO27 | MAX98357A DIN | 再生データ |
| ESP32 3.3 V | INMP441 VDD | 5 V/6 Vへつながない |
| 共通GND | INMP441 GND、L/R | L/Rはマイク側でGNDへ短く接続して左チャンネルに固定 |
| mini560 #1の5 V/GND | MAX98357A VIN/GND | 電源はAWG20等の既存分岐線。I2S信号GNDと共通 |
| MAX98357A SD/MODE | 同基板VIN | 左チャンネル選択。実物が購入したAdafruit版であることを先に確認 |
| MAX98357A GAIN | 同基板VIN | 6 dB設定。設定後の電源再投入時に有効 |
| MAX98357AのSPK +/− | φ20 mm・8 Ω・1 Wの1個 | 2本ともスピーカーへ。**SPK−をGNDへつながない** |

GAIN→VINは6 dB、SDの高電位は左チャンネル出力、スピーカー出力は接地しない差動出力です。[購入したAdafruitアンプの端子仕様](https://learn.adafruit.com/adafruit-max98357-i2s-class-d-mono-amp/pinouts)

現行の通線表は、マイクのVDD・GND・SCK・WS・SD・L/R（L/RはGND固定）の6芯と、スピーカー2芯を合わせた計8芯です。L/Rをマイク基板上でGNDへジャンパする場合は導体を1本減らせますが、既存の8芯候補と`SH6`+`SH2`の設計値は6+2芯として扱います。既存候補SH2ピンはAWG28リードなので、細孔へ通す場合は外径を確認します。初期にはAWG26等で直結し、熱収縮材と固定穴で接続点へ引張りを掛けない方法を選べます。

省部品版は音声PCMの振幅を25%に下げます。録音の感度は変えず、再生だけを縮小し、画面に「音声出力25%」と表示します。**これは1 W以下を保証する電力制限ではありません。** 実アンプ・スピーカー・音源で小音量から確認し、歪みや温度、必要な音量を判断します。5 V・8 Ωでアンプの最大出力が1 Wを上回ることは、上記一次資料で確認しています。

## 停止と測定を購入なしで分ける

| 確認 | 手持ちで行う内容 | まだ保証しないこと |
|---|---|---|
| 手動停止 | 既存スイッチを棚外から指で操作できる位置に保持。台で機体を支え、OFFで3系統すべての給電が落ちることを電圧で確認 | リレー/監視回路の自動遮断、無人時の故障安全 |
| ソフト脱力 | Web「脱力」、起動時の出力OFF、再読込で再起動しないこと、電池喪失ラッチを維持 | 電源が切れたという意味ではない。PWM消失時のサーボ挙動も実物確認 |
| 通信断 | 操作クライアント切断時に速度/PTT/standを解除。1.5秒の指令期限でPWMを停止し、再開は明示的な起動操作に限定 | 直ちに全サーボを無電源にする処理ではない。PCAの残留PWMは手動停止で確認する |
| サーボV+ | `servo_rail_verified=false`のまま、既存主電源スイッチと利用可能なPCA OEを使ってV+を実測。VBAT復帰後もWeb UIの「立つ」を再度押す | V+の自動検知、断線検知、ソフトだけの独立遮断 |
| I2C/CPU故障 | I2C失敗時の停止再送・再通電禁止、CPU監視を維持。係員が既存スイッチで遮断 | I2Cが切れたPCAの最後のPWMはソフトでは消せない。ウォッチドッグ再起動までの停止保証もない |
| 電圧/抵抗 | DT830BのDC電圧レンジで電池/6 V/各5 V/3.3 V/分圧を並列測定。抵抗・導通は必ず無電源で確認 | 電池電流・突入ピーク・平均電流・連続出力能力を測定した扱いにはしない |
| 単体サーボ | ホーン/荷重を外した1個だけで、定格電圧・方向・中立・可動角・電圧低下を段階確認 | 12軸/20軸の同時電流、拘束電流、フルドレス支持を保証しない |
| 荷重/温度/過渡 | 家庭のはかり・既知の水容器・所有温度計を流用。必要なDCクランプ/記録器は借用を先に検討 | 機械仕事率からモーターの入力電流を作らない。触感だけを温度数値にしない |

DT830Bは互換品の機種名だけでは、電流端子のヒューズ・連続測定時間・定格を確定できません。**今回の手順は電圧端子での限定測定までです。** サーボ1個でも起動ピークは未測定なので、10 A端子へ直列に入れる手順を無条件に提示しません。電流測定を追加する場合は実物説明書と制限電源/適合計器を確認し、まず借用する選択肢があります。DCクランプを購入しないことと、全機電流を確認済みとすることは別です。

スイッチの表示10 Aと既存ヒューズ15 Aの保護協調は未検証です。この組合せを短絡保護の合格とせず、初期は支持台上の有人・段階試験に限ります。ヒューズを省く/太くする、PCA異常を無視する、機体から離れて通電する変更はしていません。自動停止の独立経路が必要な運用へ広げる際は、その時点で方式を決めます。

## ビルドと段階確認

```sh
# 通常版。従来のLED/DFPlayer対応、再生振幅100%。既定環境もこれ。
.venv/bin/pio run -d firmware -e esp32dev

# 手持ち構成。LED/DFPlayerなし、I2S再生振幅25%。config.py から生成した
# PRINT_FIRST_GAIT（候補体高115 mm）を使う。候補profileは未採用。
.venv/bin/pio run -d firmware -e esp32dev_print_first

# 単体校正用。`/cal?ch=&us=`で選んだ1軸だけを出す。全機への投入はしない。
.venv/bin/pio run -d firmware -e esp32dev_print_first_cal

# ホスト回帰。実機やシリアルポートには接続しない。
.venv/bin/python firmware/tests/run_print_first.py
.venv/bin/python tools/tests/firmware_run.py
```

`platformio.ini`の省部品フラグは`TACHIKOMA_PRINT_FIRST_PROFILE=1`、`TACHIKOMA_STATUS_LEDS=0`、`TACHIKOMA_DFPLAYER=0`、`TACHIKOMA_AUDIO_VOLUME_PERCENT=25`です。0/1以外の搭載フラグや0〜100以外の音声振幅はコンパイル時に拒否します。LEDだけ/DFPlayerだけを後から有効にする組合せも確認します。通常版の20軸割当・幾何・歩容・サーボ定数は維持します。省部品版だけは`hardware/src/config.py`の`PRINT_FIRST_GAIT`から生成した`print_first_gait.h`を選び、候補体高115 mm・歩幅18 mm・周期2.4秒などを使います。この候補profileは未採用で、最終simと実機の歩行合格を示しません。低電圧閾値は通常版と共通です。

1. **PCA現物確認前:** サーボ無接続で、電源の出力確認→ESP32単独→INMP441/アンプ/スピーカーの裸配線の順に進める。表示のPCA通信異常は残してよい。歩行はできず、音声のみ先に確認する。
2. **音声:** PCを本体と同じネットワークに置き、下記`--mock`でPTTからテスト音までを確認する。これは固定の疑似応答・試験音で、自然会話の合格ではない。
3. **PCA現物確認後:** 2枚のVCC/GND/A0/I2Cと無出力を確認。単体校正版ではサーボ1個ずつ、ホーンや荷重を外して扱う。通常/省部品通常版へ戻して、明示的「起動」まで出力OFFであることを確認する。
4. **組立:** 頭無し/片脚等、採用した機構と配線だけを段階確認。全装備の収納・5 V腕保持・足裏・実電源能力を各課題で満たすまで、ソフトビルドを完成機の合格に読み替えない。

```sh
# PCだけの通信自己試験。ダミーESP32を使う。
.venv/bin/python tools/voice_bridge.py --mock --self-test

# 実配線を後日確認する際。本体APへ接続したPCから。今回この実機コマンドは未実行。
.venv/bin/python tools/voice_bridge.py --mock --host 192.168.4.1
```
