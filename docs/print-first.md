機構freeze2前の候補を最終品として扱わないため、設計必要数と今印刷可数を分けます。現行assemblyから算出した**量産未解放の設計必要数**は **body16＋legs20＋TPU靴4＋PLAスペーサー16＝56個**です。body16には頭上部と中央カメラの印刷逃がし部品を各1個含めています。機構freeze2、足の厳密検査、実物適合、材料残量のゲートをすべて通過するまで、今印刷可数は **0個**です。

材料節約の初回内数は **31個**（body各1の16個＋各ユニーク脚STL1の10個＋TPU靴1個＋スペーサー4個）とし、適合後の残りは **25個**（legs10＋TPU靴3＋スペーサー12）です。初回内数・残数も設計必要数56の内数で、今印刷可数0を変更するものではありません。旧レビュー値54／初回29／最大58は比較値として台帳に残します。

### 少量試作の順序と合否

`currently_printable_quantity=0` のまま、実測に必要な最小試作だけを順に判定します。LD保持が不要と確認できた場合は治具を省略し、印刷済み品を増やしません。

1. **LD適合治具（必要時のみ）**: `ld220_cradle`、`ld220_cap`、`ld220_horn_adapter`を各1個。ケース外形・取付軸・ホーン径/PCD・ねじ・工具進入を実物で照合し、保持でき、干渉せず、無理な押し込みなしに取り外せること。3種とも非本番で、候補値の実測前採用はNo-Goです。
2. **TPU靴1個**: 1脚へ取り付け、四隅の接地、保持/引抜き、足裏の滑り、低速可動、工具・配線の進入を確認します。静荷重を段階的に加えて白化・裂け・永久変形・接着剥離がなく、硬いトゥが先行接地しないことを合否にします。接触力・材料強度・連続歩行は別ゲートで、合格を全4個の解放へ拡張しません。
3. **隠し補強1個（候補形状を確定できた場合のみ）**: 既存部品の内側へ仮合わせし、外観面を変えず、支持面の全周接触、ねじ/接着面、工具・配線経路、静荷重時のたわみと脱落を確認します。候補未確定の間は数量0・量産未解放とし、首補強候補11種を同時印刷しません。

各段階の合否は、使用STLのSHA、材料/積層、対象個体、寸法、荷重、変形、写真/動画を記録してから次段へ進めます。ホスト検査やnative traceのPASSだけで実機完成とは判定しません。

電池・砲身音声部品の候補占有は [`tools/print_first_components.py`](../tools/print_first_components.py) が、砲身ポケットの実寸候補をCannonローカルから `base_link` へ一度だけ変換して出力します。診断例は [JSON](../outputs/print-first-20260905/components/diagnostic.json) と [図](../outputs/print-first-20260905/components/diagnostic.png) です。電池は34×105×24 mm・180 gを候補として記録していますが、基準位置は機械統合から引数で与える未確定値です。診断例の `[0,-6,11.6]` mm は明示引数で置いた候補位置であり、収納確定値ではありません。マイク14×11×3 mm、スピーカーφ20×5 mmの対象部品寸法・質量、棚との干渉、配線経路は未確認です。配線等の97 g残差は固体箱にせず占有検査から除外します。

## 足裏の荷重と根元断面

`tools/check_print_first_feet.py` は、靴STLの実三角形から傾斜時の最低支持点を抽出し、φ10プラグ軸からの支持中心と最外支持点の偏心を記録します。現在の設計横傾斜±15度では、支持中心の最大偏心は約29.59 mm、最外支持点の最大偏心は約30.05 mmです。これは接触圧力分布やTPU変形を測った値ではありません。

同検査は `leg_foot_bored.stl` のプラグ根元 z=0 mm 断面も実測し、面積78.41 mm²、最小断面係数97.86 mm³を記録します。22.4 Nは従来の固定参照値であり、最終シムの最大鉛直接触力・水平接触力の代用にも、機械合格にも使いません。最終シムJSONを `--simulation` で渡した場合だけ、記録された鉛直/水平力を別々に読み、偏心曲げ・水平せん断・根元曲げの要求値を算出します。力の成分が無い場合は推測せず `UNVERIFIED` とします。CAD中実断面の要求値は、印刷周壁・充填・積層異方性・局所応力・座屈・接着・クリープを含みません。

`--simulation` に渡すJSONは、`model_kind` が `final_integrated` / `print_first_final` / `frozen_integrated` のいずれかで、モデル本体と元URDFの完全SHA-256、凍結hash、body/feet/legs台帳、4脚の `tibia` フレーム根元座標を持つ必要があります。`selected_derate50.json` など旧感度sim、候補靴の `foot_candidate_dir` だけを持つ結果、台帳hashのない結果は `UNVERIFIED_LEGACY_SIMULATION_MODEL` として荷重を読まず、正式な足検証へ流用しません。

```sh
.venv/bin/python tools/check_print_first_feet.py \
 --directory outputs/print-first-20260905/feet \
 --simulation <最終形状を使ったシム結果.json>
```

最終シムがまだ無い場合も、`--simulation` を省略して幾何と偏心だけを更新できます。結果の幾何欄が局所確認済みでも、`contact_load_demand.status` は最終接触力待ちになります。この二つを同じ合格と読まないでください。

## 試作から全機までの順序

1. 採用候補STLのハッシュ、材料、向き、設定、置換対象を台帳で確認する。
2. **1靴・1脚分の適合試作**（サーボ1個、実ねじ締結、足裏接地、支持、引抜き、たわみ、温度）と、**電装ベンチ**（電源・停止・電圧・通信・音声）を並行して記録する。ここでは残数を印刷しない。
3. 機械CAD・組立経路・LD保持の統合はすでに先行しており、電装ベンチと並行して進める。1靴・1脚の現物適合で得た寸法・保持・配線の差分をこの統合CADへ反映し、最終固定部品・棚・カメラ・音声・電源を同じ配置で再確認する。
4. 最終統合形状・質量・接触材料・採用profile headerで、実C++経路を含む停止、逆旋回、長時間前進、低摩擦、接触力（脚別の鉛直/水平成分とφ10根元モーメント）を再実行する。物理シムの未測定項目は合格にしない。
5. **単体適合試作と、全CAD/組立経路/実C++物理試験の両方が合格した後だけ**、マニフェストの残数を印刷する。青殻の既存加工案と新規印刷案は排他的に選び、その後に全機を組み、歩行を実機で確認する。

残数印刷を量産扱いにする条件は、上記の単体適合・電装ベンチに加え、最終統合CAD/組立経路と実C++物理試験が揃うことです。現在はこの条件を満たしていないため、残数印刷・全機歩行・実機完成を完了扱いにしません。

印刷済み品、元STL、元3MF、検査履歴は保管します。公開時はマニフェストの採用候補と除外候補を分け、シムのキャッシュ・実行ファイル・一時試験ファイル・外部記録の個人情報を配布しません。
