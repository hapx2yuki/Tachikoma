# STL保存処理の独立レビュー

`hardware/src/lib.py::export` と `to_trimesh` を読解し、旧STL保持、空/不正値、法線、閉じた空洞を実際に検査した。本流libの修正は機構担当が実施し、独立担当は `tools/tests/test_export_stl.py` を追加した。最後に重複/ゼロ面を向き変更なしで除去する処理も確認し、実tibiaと空洞への不要面追加の双方で回帰した。

| 内容 | 結果 |
|---|---|
| 正常箱のSTL保存 | 合格 |
| 欠面、空、NaN、Inf、内向き面 | 保存を拒否、旧ファイルのbytes保持 |
| メモリ上は正常な箱がfloat32 STLで潰れる | 保存を拒否、旧ファイル保持 |
| 書込途中の容量不足相当例外 | 同一フォルダの一時ファイルだけが失敗し、旧ファイル保持・一時ファイル削除 |
| 最終os.replaceでの例外 | 旧ファイル保持・一時ファイル削除 |
| 鏡映したManifold | 正しい位置、閉体、外向き、体積24mm³ |
| 独立した2閉体 | 共通exportの既存用途を保って許容。必要な一体制約は部品別検査へ |
| 外箱10³−内箱6³の閉じた空洞 | 修正前1216mm³へ変化、修正後784mm³を保持 |
| 閉体・向き一貫・正体積だが空洞の面向きが誤った1216mm³出力 | sourceの784mm³との不一致を検出して保存拒否 |

新たに再現した根因は `to_trimesh` の `process(validate=True)`。内壁は空洞を表すため負向きだが、各閉曲面を外向きへ直す処理が内壁も反転し、216mm³の空洞を足し算に変えていた。`process=True, validate=False` と未処理の双方では正しい784mm³を保持する。`stl-export-cavity-reproduction.json` に原因を分離した結果を保存。

最終実装はManifoldの面順序を保存し、STL再読後の閉体・面向き一貫・有限頂点・有限正体積を検査する。さらに `abs(STL−Manifold) ≤ 0.01mm³ + 1e-6 × abs(Manifold)` の体積照合を行う。その後、同一フォルダの一時ファイルを完成させてから `os.replace` で出力先を置換する。これにより異常形状だけでなく、途中書込失敗でも旧STLを保持する。

`split()`の面連結数だけで共通exportを一体限定にはしない。閉じた空洞の外壁と内壁も別閉曲面になるため、一般の複数面判定で拒否すると正しい中空体を壊す。独立部品が一つでなければならない条件は部品の設計に従って別途検査する。

実行: `.venv/bin/python -m unittest tools.tests.test_stl_export tools.tests.test_export_stl -v`。機構担当3試験＋独立9試験の12試験すべてPASS。`stl-export-peer-tests.log`は修正前の空洞失敗、`stl-export-peer-tests-final.log`は最終合格。再現は一時フォルダだけを使い、本流STLや実機には書き込んでいない。

この検査は形状とファイル保全を対象とし、全機体の組立可否・印刷強度・電源断時のディスク永続性は認定しない。
