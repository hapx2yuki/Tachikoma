# 第2次 機構・印刷・組立監査（2026-09-05）

**現行一式をそのまま組み立てて歩かせられる設計とは確認できない。** 腕と音声の確定した内部干渉は修正した。一方で、頭内の実サーボ占有、脚カバーとシャーシ、頭固定、足の接地、配線後の支持強度には未解決の問題が残る。既存検査の PASS と実機成立を同一視しない。

## 対象と検査方法

- `hardware/src` の12 Pythonファイルを全読解。形状生成・取付原点・サーボ向き・ホーン/ねじ・負形状・組立順を確認した。
- `model` の58 STL、`hardware/stl` の41 STL、同ディレクトリの26 3MF、ルートの1 3MFを機械読込した。全頂点/面、有限値、面参照、閉形状、連結数、体積、外包、ZIP CRC、全 `.model` XMLを検査した。表示用の一部だけを対象にしていない。
- `kit_assembly.py`、全配置JSON、`extract_meshes.py`、`make_head_eyecut.py`、印刷生成、脚/ねじ/腕/目/音声/カメラ/首の検査を全読解。新しい診断には元STLの実体ブーリアン、元C++到達姿勢、面断面、レイ、差分体積を使った。
- パス・SHA-256・読み方・結果・根拠は [coverage-mechanical.json](coverage-mechanical.json)。生成後のSTL/3MFの鮮度は最終再集計時点を使う。
- MuJoCo、全体の質量・慣性、URDF、購入ケースを含む全衝突は [simulation](simulation/) の担当検査を参照する。電子回路・電流・購入型番の一次資料は全体報告、Cabin収納は [cabin.md](cabin.md) に分離した。

元の `~/Downloads/TACHIKOMA.3mf` は今回の環境に見つからない。配置JSONの過去の組立座標抽出記録を、元3MFを再読した確認済み情報として扱っていない。ルートの `TACHIKOMA_Phase0_PETG.3mf` は元キット組立プロジェクトの代用にならない。

### 口の挿入とシャーシの受け座

固定部品を全組合せで調べると、口のBall–シャーシ1149.47mm³、Neck–シャーシ115.51mm³、Cap–シャーシ0.219mm³、Cap–Neck112.88mm³が残っていた。これは座標の違いではなく、実体そのものの交差だった。Ball/Neck/Capを配置した負形状に片側0.3mmを加え、シャーシ内側へ必要な逃げを設けた。Cap–Neckには片側0.2mmと引き抜き方向の連続包絡を加えた内部座を作った。

シャーシの正面90度のねじ耳は、逃げだけだと穴周囲が薄くなる。そこだけφ10mm・高さ3mmのカラーを追加し、穴φ3.2mmの外に半径方向3.4mm、上下方向5mmの連続した環状支持を残した。この穴のねじ有効長は旧図から3mm増える。ほかの脚/腕/PCA/電池/首/頭の支持領域は除去0、追加カラーと既存部品の交差0。頭を実際に固定する支柱が未設計であることは別の未解決事項である。

最終sourceはシャーシ1閉体、体積54609.82mm³。口3部品との材料交差0、下側から30mmの挿入を0.25mm刻みで調べた各121姿勢も0。Neckは1492.96mm³の1閉体で、BallとCapの挿入各121姿勢、マイクの97位置が0。これらは隠れた受け座の修正であり、口の原型表面を変更していない。[mouth-chassis-source.json](mouth-chassis-source.json)、[audio-assembly-cap-seat-source.json](audio-assembly-cap-seat-source.json)

### 固定爪と脚Guardに残る組立干渉

手の旧検査は、交差50mm³未満とレイ残差1mm未満を「現物合わせ許容」として合格させていた。根拠がないため廃止した。前腕・mount・爪・指3・指先3の9部品全36組を個別検査すると10組で交差する。mount–爪4.628mm³、爪–指0.058〜0.076mm³、爪–指先15.878〜15.881mm³、指–指先17.071mm³。中心面のレイ残差は最大0.0397mmだが、面の一致だけでは全形状の組立を保証しない。元の圧入量・公差・挿入経路が未確認なので、`check_hand_assembly.py` と `check_arm.py` はNGを維持する。原型の可視指形状を勝手に削っていない。[hand-assembly/final.json](hand-assembly/final.json)

脚Guardは旧配置最適化が支持殻へ約1mm埋める目的で作られ、実受け座が未生成だった。ThighGuardの1211.94mm³（約81%）、ShinGuardの1146.76mm³（約78%）が殻へ食い込む。Guard側だけを切る候補は各210〜211mm³、3体/2体へ分裂したため不採用。支持殻側の受け座も6候補を検査した。局所4案は1閉体でも26方向への初動がすべて干渉。開放大腿案は外面724.7mm²を失い、開放脛案は542.5mm²を失って283mm³が分離するため、いずれも不採用。骨格との交差も残る。意匠部品同士の交差を接着代として通過させない。[guard-seat-candidates.md](guard-seat-candidates.md)

## 足裏：実際の150%つま先で再評価

倍率修正前の表示モデルのつま先は長さ16.75mm、体積730.45mm³だった。印刷された150%形状は長さ25.125mm、体積約2465.28mm³。第1次監査の接地差は前者に対する数値であり、実物150%の結論として再使用してはいけない。

150%修正後、既定体高115mmの無移動保持で、最も低いつま先は基準地面から **−13.335mm**、TPU足裏は **+8.699mm**、差は **22.034mm**。硬い足本体もTPUより3.875mm低い。4脚全てでつま先が先に接地する。体高110〜130mm、停止保持・その場SWAY・4段階の歩幅を調べても問題は消えない。[toe-contact-after-scale.json](toe-contact-after-scale.json)

有限な改修候補を、体高5種・命令13種・96位相・4脚の24,960姿勢から得たピッチ+膝の範囲 −42.073〜8.978度で比較した。図は [foot-support-candidates/comparison.png](foot-support-candidates/comparison.png)、全数値は [comparison.json](foot-support-candidates/comparison.json)。

| 候補 | 最低接地差/必要な変更 | 判定 |
|---|---|---|
| 足ソケットの小さな回転 | ±15度内の最良でも硬部がTPUより最大24.04mm低い | 小変更だけでは全範囲を満たさない |
| 全角度の回転探索 | 360度全域1441候補でも最良が−9.91mm | 向きだけで解決しない |
| 球面支持R15 | 全域2.073mm先行接地。ただし旧足裏より底面を36.59mm延長 | 外観・たわみ・体高への影響が大きく不採用 |
| つま先下面のTPU靴1.5mm | 全域1.642mm以上先行接地。足本体との交差約4.7e-7mm³ | 見た目変更を伴う候補として保存。現行STLへ未採用 |

TPU靴は各つま先の現物150%形状に沿わせ、内側の足本体との接合部だけに隠れた座を設けた。元の根元は各29.0〜29.6mm³が足本体へ交差していたため、単なる「接着代」として無視しない。試作形状の連結片1個を除いた場合も、除去量34.91mm³を記録している。

荷重は最悪の1本へ3.8kg×0.6×g=22.37Nを与えた単純曲げで、根元の最大応力2.64MPa。接着接触面47.0〜49.5mm²に対する平均力は0.45〜0.48MPa。**これは接着の許容値ではない。** 剥離、2g以上の衝撃、薄い足側の局所破壊、摩擦係数、TPUクリープを未確認として残す。別材接触モデルでの横滑り比較はsimulation担当の候補試験へ渡した。

## 頭内：ケースを含めると成立していない

下向き軸の脚ヨーサーボは、取付タブから本体が上へ伸びる。現行寸法ならケースはchassis z7〜35.2mmに達する。`make_head_eyecut.py` は反対側の `ABOVE_TAB` を使い、高さ18mmの仮箱で頭内を削っていた。腕側も実ケースはz6〜25.5mmに対して旧仮箱12mmだった。

独立した全ケース検査では、脚ヨー–目本体/保持板、脚ヨー–HeadTop、肩ピッチ–前脚ピッチに数百〜数千mm³の交差がある。同じ固定リンク上の部品同士はMuJoCoの自己接触として出ないため、別の組立検査が必須である。4ケースだけで得られた旧収納候補は目のサーボ/保持板を含まず、採用できない。詳細は [simulation/all-pairs-native-20servos-before-final.json](simulation/all-pairs-native-20servos-before-final.json) と収納探索記録を参照する。

購入済みの機種は資料間で不一致がある。DS3218、Hiwonder LD-20MG、LD-220MGの3系統を同一外形として扱わない。メーカーのDS3218図のタブ下27.7mmとconfig28.2mmにも0.5mm差がある。ケースの主箱だけでも不成立なので、この差によって問題全体が解消することはないが、再製作の前に実購入機種を確定する必要がある。

### カバーとシャーシ固定

保持姿勢のchassis–thigh_capは前脚約116mm³、後脚約411mm³。外面2万点試験でも前脚532/519点、後脚1278/1290点がシャーシ材料内にあり、前脚は全て上向きの可視外面である。内部を中空化するだけでは直らない。

前脚の交差半径は69.35〜84.83mm、後脚は72.03〜87.10mm。取付耳だけを削除/内寄せしても前脚は本体円板r72と交差する。coxa–capの保持時約10.7〜13.6mm³も別に残る。無断でカバー上面を欠く加工は実施していない。

頭固定の7穴はr78にあるが、7本とも垂直軸線がHeadTopを通らない。頭位置の1mm不一致をconfigの11mmへ統一した後、旧4mm耳から頭までのサンプル最短距離は前3点5.69〜5.95mm、後4点17.57〜17.62mm。口逃げのため追加した正面カラーは3mm高く、表面から頭まで2.69mmになるが、固定穴の軸線が頭へ届かない問題自体は解消しない。従来の「現物合わせで固定」では、支持柱・受け座・ねじの荷重経路が欠ける。半径78/70/62/54、頭中心へ11mm寄せた62/54/46の計49位置も比較した。中心を寄せて殻に届く後部候補は、φ6支持柱が後脚ケースへ最大約794mm³食い込む。前・後・目・ケースを同時に扱う取付再設計が必要である。[head-attachment-candidates/comparison.json](head-attachment-candidates/comparison.json)

## 首・締結・材料・組立の残り

- 首はφ6/8、出口y−80/−75/−70/−65の8候補を作成。全て1体で閉形状。8mm孔の先端壁は丸棒12mmに対して最小2mmになる。配線候補はCabin側のφ8・曲率R25へ接続する。
- 600g×2g、68MPa、応力集中係数2.5という既存仮定では、首の最小安全率は中実3.105、壁1.6mm・40%密度2.723で、要求3を下回る。支配断面は孔の先端ではなく基部y−43.29。`4walls/40%`だけで「中実同等」と判断しない。[neck-wire-candidates/comparison.json](neck-wire-candidates/comparison.json)
- HeadTop–首89.23mm³に対する単純な頭側切削は、サンプル300,000点中651点の後向き外面を失う。TailJointはその位置を覆わない。不可視加工だと断定していない。[head-neck-cut-visibility.json](head-neck-cut-visibility.json)
- 別担当の首候補は前側y−59〜−43の幅44mm補強と実Head+0.3mmの逃げで、φ8通線、安全率3.86、HeadTop交差0まで具体化した。ただし元の首にはTailJointBlue約3282mm³、Ball約2048mm³、CabinFront約1200mm³、CabinEye約878mm³の占有重なりがあり、候補の首だけで完成とはしない。TailJointの頭側半分は中実で、首を通せる中空部ではなかった。
- 脚の細長いリンクは既存検査の中実強度と、殻+40%密度の感度を分けた。梁モデルは層間/穴周り/クリープ/ねじ緩みを表さない。tibiaの旧係数で中実約2.11、殻+40%約2.01の安全率に留まる。
- `check_screw_bosses.py` の材料充填率はボス位置の検査であり、全ねじの長さ、ドライバー経路、ナット挿入、締付けによる保持を一括保証するものではない。今回の内部腕修正ではホーン座/ケースフレーム保持を個別検査した。
- 目のホーン中心ねじは設計上アクセスが乏しく、摩擦嵌合と接着だけに依存する記述が残る。目は小荷重でも転倒時の軸方向抜け止めを実機確認する。サーボホーンの寸法/軸歯数は購入機種照合が先である。
- Cabinの一体ソリッド、Pegの6.3075mmずれ、電装室/配線通路/着脱棚は担当の [cabin.md](cabin.md) にある。元の「15%の中空だから電装が入る」という解釈を採用しない。

## 印刷と検査結果の読み方

最初の99 STLは全て閉形状だった。元の左右肘部品と任意スタンドの複数連結片は用途として別記している。「閉じている」は組立可能という意味ではない。

口逃げを加えたシャーシはCAD内では閉体でも、STL保存後の再読込でゼロ体積の2枚面が分岐し、非閉形状になった。最終統合前の実STL検査が検出した。0.001mmの簡約で解消し、体積差は+0.00303mm³、除去0.000619/追加0.003649mm³。口・支持材・挿入の再検査も合格した。`lib.export()` はSTL化したバイト列を再読込して閉形状/向き/有限正体積を確認し、不正なら例外を出して旧出力を保持する。単なる警告表示で生成成功にはしない。[chassis-stl-roundtrip.json](chassis-stl-roundtrip.json)

独立試験では、既存の `to_trimesh()` にあった `process(validate=True)` が閉じた内部空洞の面も外向きに反転する欠陥を検出した。外10mm箱から内6mm箱を引いた正体積784mm³が1216mm³へ増えていた。`validate=False` にしてManifoldの面順序を保ち、保存後体積をsourceと絶対0.01mm³＋相対1ppm以内で照合する。全生成物はこの変換で再生成する。保存は同じディレクトリの一時ファイルへ完了後に置換し、容量不足や置換失敗でも前のSTLを保つ。正常・鏡映・内部空洞・複数閉体と、欠面・空・NaN・途中書込・置換失敗を含む独立8件＋基本/実tibia3件の計11件が合格した。

ルートの `TACHIKOMA_Phase0_PETG.3mf` は現行tibiaと体積6.848%差、femurと2.097%差/最大頂点差7.596mmがある。既存26 3MFだけを見る第1次調査から取りこぼしていた1ファイルである。新たな腕/音声/coxaの生成により、関連する旧3MFも再照合が必要になる。上書きせず、元の印刷履歴と再生成候補を分ける。

`claw_mount_L` の2壁/15%という個別設定、印刷数量や旧設定の警告は機械台帳へ残した。STL読込・スライサ設定・実印刷の材料/層接着は別の確認段階である。

未解消の足接地やHead–首を検出した診断は、終了値1を維持する。`check_shin_arm_leg.py` に残る最大0.25cm³の既知残差許容は、全干渉0を保証しない。全体の実部品ブーリアンと最終ログで補う。ブーリアンのNone/NaN/負体積と、STL保存後の不正形状は正常と見なさない。

## 既購入・既印刷品を生かす順序

1. 購入サーボ/UBEC/カメラ改版を実物と照合し、頭内のケースと固定座を同時に解決する。今の頭・シャーシの追加印刷は確定寸法と支持構造が揃うまで進めない。
2. 既存外観の足・つま先を保って、候補TPU靴と根元の隠れた座を比較する。荷重・接着・横滑り・転倒での試験が先。
3. source修正済みの腕/音声は新STLを個別部品で無通電仮組みし、全挿入経路と低トルク可動を確認する。脚の本体と外観一式を付けた通電とは分ける。
4. 電源枝ごとの電流/降圧温度/最低電圧と、吊った状態のゼロ・全遷移を実測する。机上の公称トルクで連続作動を保証しない。
5. 機構・電気のゲートを満たした後に、支持下での低速1脚、4脚保持、低速歩行、外観一式の順へ進む。今回の計算だけで実機合格とはしない。
